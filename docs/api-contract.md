# API contract (web/ ↔ api/)

The only routes the frontend may call. Any PR that adds or changes a route updates this file in the same PR and posts on the board when it lands.

Base URL: same origin, paths start with `/api` (served by `netlify/functions/api.mts`; locally `npx netlify dev` on http://localhost:8888). All bodies are JSON. Sessions are stored in Netlify Blobs (store `sessions`, key = session id).

## Types

```ts
type Source = "user" | "inferred" | "unknown";
type Status = "proposed" | "approved" | "locked";

interface Node {
  id: string;            // "n1", "n2", ... stable within a session
  label: string;         // 1-5 words, shown in the bubble
  detail: string;        // one or two sentences
  kind: "goal" | "feature" | "page" | "component" | "data" | "api" | "style" | "constraint";
  source: Source;        // who it came from (never changes after creation)
  inventiveness: number; // 0..1, only meaningful for "inferred" (0 = obvious, 1 = creative leap)
  importance: number;    // 1..5, how much the user should weigh in
  status: Status;
  parent: string | null; // tree parent node id; root goal has null
  evidence: string[];    // exact user quotes that support it (empty for inferred/unknown)
  turn: number;          // chat turn that created it
  facet?: "design" | "audience" | "functionality" | "cost" | "goal"; // Ben's prompt-engineering facet (ai/taxonomy.ts). Optional; UI may group/color by it.
  decision?: Decision;   // optional picker shown in the drill-in view (web/src/DrillIn.jsx). Not generated by ai/ yet.
}

// Drill-in decision payload (Figma "Branding drill-in"). Without it, the drill-in bubble shows `detail`.
// guess: accent line "Claude's guess: …"; note: grey caption (null hides it, missing = status default).
type Decision = { guess?: string; note?: string | null } & (
  | { type: "choice"; options: { label: string; glyph?: string; font?: "serif" | "sans" }[]; pick?: number } // 2-4 option tiles
  | { type: "scale"; scales: { left: string; right: string; value: 0 | 1 | 2 | 3 | 4 }[] }                // 5-point sliders
  | { type: "drafts"; drafts: string[]; pick?: number }                                                     // pick-one drafts + "Write my own"
);

interface Edge { from: string; to: string; relation: "has" | "needs" | "informs"; }

interface MindMap { nodes: Node[]; edges: Edge[]; }

interface Message { role: "user" | "assistant"; text: string; node_id?: string; } // node_id set for bubble brainstorms

interface BuildAudit {
  totalElements: number;
  tracedElements: number;
  coveragePct: number;
  nodeBreakdown: Record<string, number>;
  untracedNodes: string[];
}

interface Build {
  id: string;            // "b1", "b2", ...
  status: "pending" | "done" | "error"; // builds run in a background function; poll until not pending
  error?: string;
  html: string;          // full standalone HTML; every traced element has data-mc="n3 n7"
  trace: Record<string, string[]>; // node id -> list of data-mc-el ids it informed
  checkpoint_id: string;
  audit?: BuildAudit;    // server-side traceability audit metrics
}

interface Checkpoint { id: string; label: string; turn: number; map: MindMap; build_id?: string; }

interface Turn { status: "pending" | "done" | "error"; error?: string; changed: string[]; started_at: number }

interface Session {
  id: string;
  messages: Message[];   // main chat only
  map: MindMap;
  builds: Build[];
  checkpoints: Checkpoint[];
  turn?: Turn | null;  // latest chat turn (async on Netlify)
  next_node_seq?: number;
}
```

**Traceability rule:** every element in the generated HTML that a node informed has `data-mc-el="<unique id>"` and `data-mc="<space separated node ids>"`. The preview iframe includes a small script (added by `api/`, not the LLM) that `postMessage`s `{type:"mc-hover", nodes:[...]}` to the parent on hover and listens for `{type:"mc-highlight", nodes:[...]}` to outline matching elements. For the side panel's Design widgets it also answers `{type:"mc-inspect", id, nodes}` with `{type:"mc-inspect-result", id, items:[{el, tag, text, textEditable, fontSize, fontFamily}]}`, applies `{type:"mc-style", el, fontSize?, fontFamily?, text?}` live, and scrolls to and flashes `{type:"mc-flash", el}`.

## Abuse protection & input limits

To prevent runaway Opus usage and abuse on the public API, the following limits are enforced:

- **Chat text length:** Max 4,000 characters for prompt extraction (`POST /api/sessions/{sid}/messages`) and bubble chat (`POST /api/sessions/{sid}/nodes/{nid}/chat`). Exceeding returns `413 {"detail": "chat text exceeds maximum length of 4000 characters"}`.
- **Node text length:** Max 80 characters for labels and 500 characters for details on `POST /api/sessions/{sid}/nodes` and `PATCH /api/sessions/{sid}/nodes/{nid}`. Exceeding returns `413 {"detail": "..."}`.
- **Node limit:** Max 60 nodes per session map. Adding more via `POST /api/sessions/{sid}/nodes` returns `409 {"detail": "maximum map node limit of 60 reached"}`.
- **Session cooldowns:**
  - Chat turns: Max 1 chat turn per 5 seconds per session. Calls within cooldown return `429 {"detail": "chat cooldown in effect; please wait before sending another message", "retry_after_s": number}`.
  - Builds: Max 1 build start per 8 seconds per session (`POST /api/sessions/{sid}/build` or `POST /api/sessions/{sid}/builds/{bid}/edit`). Calls within cooldown return `429 {"detail": "build cooldown in effect; please wait before starting another build", "retry_after_s": number}`.

Errors: `404 {"detail": "..."}` for unknown session/node, `413` when input text exceeds allowed limits, `409` for node cap or pending operations, `429 {"detail": "...", "retry_after_s": number}` when cooldown is in effect, and `502` when the LLM call fails or returns invalid JSON after one retry.

## AI module interface (`ai/`, wired in `api/ai.ts`)

```ts
// see api/types.ts: interface AI
updateMap(messages: Message[], current: MindMap): Promise<{ reply: string; map: ProposedMap }>;
nodeChat(node: Node, map: MindMap, history: Message[], text: string): Promise<{ reply: string; label?: string; detail?: string; suggest?: Array<{ label: string; detail: string; kind?: string }> }>;
buildApp(map: MindMap, previousHtml: string | null): Promise<string>; // HTML with data-mc / data-mc-el
```

`updateMap` may return partial nodes; the API fills defaults and enforces the rules: approved/locked nodes are never changed, `source` is fixed at creation (one exception: an `unknown` the user answers, with a quote, becomes `user`), only the user approves, and omitted nodes are kept. `updateMap` and `nodeChat` must finish well inside the 30 s function limit (cap `max_tokens`). `buildApp` runs in the background function (15 min).

With `MINDCODE_FAKE_LLM=1`, `api/ai.ts` uses deterministic canned output (no network, no key), and builds run inline.
